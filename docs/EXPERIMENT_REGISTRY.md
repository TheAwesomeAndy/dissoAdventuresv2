# Experiment registry

Generated by `scripts/build_registry_doc.py` from `docs/experiment_registry.json`. Do not edit by hand.

Each entry answers: what question, on what data, with which code, by what protocol, producing which record, checked by what, and with which known problems. Statements about v1 scripts come from reading the code during the 2026-11-21 audit (`docs/REPOSITORY_AUDIT.md`), not from file names.

## Tiers

- **v1-confirmatory**: The corrected, leak-free v1 protocol. Code-derived numbers are authoritative; see COMPUTATIONAL_ERRATUM.md for how they relate to the dissertation text.
- **v2-validation**: Post-dissertation tests of the v1 claims, run on the authorized data with committed, hash-locked records.
- **public-replication**: Run on public data. Anyone can repeat it.
- **exploratory**: Hypothesis-generating. Not corrected for the analyses tried, or superseded, as each entry says.
- **archived**: Legacy v1 chapter analyses kept for provenance. Known leakage, legacy input or uncorrected statistics. Descriptive only.
- **illustrative**: Synthetic-data demonstrations and presentation figures. They establish no empirical claim about EEG.
- **tooling**: Checks and utilities.

## CONF-01

**v1 confirmatory classification (corrected protocol)**

- **Tier:** v1-confirmatory
- **Question:** Does the BSC6 / SRP-64 reservoir code separate affective conditions on held-out participants, and how does it compare with raw ERP bins and conventional features?
- **Data:** SHAPE three-condition epochs (./batch_data, restricted); SHAPE four-category epochs (./categories, restricted)
- **Code:** `experiments/confirmatory/run_confirmatory_validation.py`, `experiments/confirmatory/confirmatory_pipeline.py`, `chapter5Experiments/experiment_zero.py`
- **Run:**
  - `python experiments/confirmatory/run_confirmatory_validation.py --data3 ./batch_data --data4 ./categories --out confirmatory_results.json`
  - `python experiments/confirmatory/check_against_manifest.py confirmatory_results.json --tol 0.05`
- **Records and outputs:** `experiments/confirmatory/confirmatory_results.json`
- **Model and encoding:** N=256, beta=0.05, theta=0.5, dense uniform W_rec scaled to spectral radius 0.9, one scalar input per electrode; a different reservoir per electrode (seed 42 + 17 x channel); full 256-sample epoch in six 42-sample bins (last 4 samples dropped); fixed SparseRandomProjection 1536 to 64, seed 20240517
- **Validation protocol:** 5 repeats x 5-fold StratifiedGroupKFold by participant; StandardScaler and LogisticRegression(C=1) fitted on training participants only; nothing is fitted before the split
- **Statistics:** participant-cluster percentile bootstrap (2000) over pooled out-of-fold predictions; within-participant permutation test with a ridge stand-in, 100 permutations
- **Seeds and determinism:** base seed 0 (three conditions) and 100 (four categories); reservoir 42 with robustness seeds 7 and 99; bootstrap 12345. Deterministic
- **Metrics:** balanced accuracy, paired contrasts, destruction-control drops
- **Checked by:** `experiments/confirmatory/verify_confirmatory.py`, `experiments/confirmatory/check_against_manifest.py`, `experiments/confirmatory/validate_provenance.py`, `tests/test_records.py`, `experiments/v2/check_v2_replay.py`
- **Dissertation:** Chapter 5. The dissertation reports 60.6% and 53.2%; this committed pipeline produces 64.3% and 54.6%. The gap is reconciled in COMPUTATIONAL_ERRATUM.md, and the dissertation text is not edited.
- **Known problems and limits:**
  - The window labels in confirmatory_pipeline.TEMPORAL_WINDOWS ('39-273ms' and so on) do not match the slices, which are quarters of the 0 to 1000 ms epoch.
  - The permutation p-value 0.0099 is the floor for 100 permutations and uses a different model from the headline. v2 repeated it with the headline model (V2-01).
  - Input is z-scored per epoch, which invalidates window-specific readings (V2-02).

## V2-01

**v2 validation of the measurement chain**

- **Tier:** v2-validation
- **Question:** Does the deployed reservoir have fading memory, does it add anything over matched non-reservoir controls, and do the v1 controls and statistics hold when done properly?
- **Data:** SHAPE three-condition epochs (./batch_data, restricted); SHAPE four-category epochs (./categories, restricted)
- **Code:** `experiments/v2/run_v2_validation.py`, `experiments/v2/data.py`, `experiments/v2/make_report.py`, `experiments/v2/config.toml`
- **Run:**
  - `python experiments/v2/run_v2_validation.py --data3 ./batch_data --data4 ./categories --cache ./v2_cache --out experiments/v2/v2_results.json --n-perm 2000 --jobs 4`
  - `python experiments/v2/make_report.py`
- **Records and outputs:** `experiments/v2/v2_results.json`, `experiments/v2/V2_RESULTS.md`
- **Model and encoding:** the v1 LIF operator, one reservoir shared by all electrodes, recurrent gain chosen as the largest grid value passing the label-free fading-memory rule (0.025); BSC6; SRP-64
- **Validation protocol:** v1 splits and readout (CONF-01), with the readout fitted in the row space of the training matrix; ten stages listed in the runner docstring
- **Statistics:** participant bootstrap (2000); within-participant permutation test with the headline estimator (2000); unbiased two-way variance components with permutation nulls (1000)
- **Seeds and determinism:** v1 base seeds; reservoir seeds 42 and 1 to 9; projection seeds 0 to 9; dynamics sample seed 2026. Deterministic: a replay of 19 values on fresh encodings equals the record (V2-06)
- **Metrics:** balanced accuracy, paired contrasts, fading-memory measurements, variance fractions
- **Checked by:** `experiments/v2/verify_v2.py`, `tests/test_reservoir.py`, `tests/test_dynamics.py`, `tests/test_evaluation.py`, `tests/test_pipeline_smoke.py`, `tests/test_records.py`, `experiments/v2/check_v2_replay.py`
- **Dissertation:** Not in the dissertation. Tests claims made in Chapters 3 to 6. Interpretation in V2_UPGRADE.md.
- **Known problems and limits:**
  - The fading-memory rule was written after its author had seen the dynamics sweep. It uses no labels. Gain 0.025 passes at 99% and 0.05 fails at 94%.
  - The default weight draw (seed 42) is the best of ten; the ten-draw means (65.1% and 55.4%) are the fair summary.
  - Section 6 of V2_RESULTS.md (windows) is computed on z-scored epochs and cannot be read as timing.
  - 2000 permutations, not the 5000 the review asked for. Zero exceedances at 16.9 and 19.2 null SDs.

## ZS-01

**Per-epoch z-scoring artefact on ERP CORE**

- **Tier:** public-replication
- **Question:** Does per-epoch z-scoring create above-chance decoding before stimulus onset on public data, and is the effect larger for a sustained component (P3) than a brief one (N170)?
- **Data:** ERP CORE N170 and P3 epoched single trials (public, doi:10.18115/D5JW4R; download into ./erpcore)
- **Code:** `experiments/zscore_artifact/run_erpcore.py`, `experiments/zscore_artifact/make_figure.py`

- **Model and encoding:** no reservoir: 28-channel scalp pattern in 15.6 ms bins under four normalizations
- **Validation protocol:** within participant: shrinkage LDA, stratified 5-fold repeated twice, fold-local standardization. Across participants: one average per participant and condition, 5 x 5 StratifiedGroupKFold, logistic regression
